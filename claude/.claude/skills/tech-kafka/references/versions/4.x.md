# Kafka 4.x deltas (4.0 to 4.3)

Overrides `references/core/` where they conflict.

## Hard requirements (4.0)

- ZooKeeper mode removed. KRaft only.
- Java: clients and Streams need 11 or higher. Brokers, Connect and tools need 17 or higher.
- Old protocol API versions removed. Brokers and Java clients (including Connect, Streams) must be on 2.1 or higher before upgrading. Non-Apache clients: see KIP-896.
- Scala 2.12 support removed. Logging moved from Log4j to Log4j2, `KafkaLog4jAppender` removed.
- Upgrade source: brokers KRaft with software and metadata version at least 3.3.x. Older KRaft: go to 3.9.x first. ZooKeeper: migrate first.

## Removed or renamed

- Broker configs: `delegation.token.master.key`, `offsets.commit.required.acks`, `log.message.timestamp.difference.max.ms`, `log.message.format.version`, `message.format.version`.
- `DefaultPartitioner` and `UniformStickyPartitioner` removed.
- MirrorMaker 1 removed.
- CLI: `--broker-list`, `--whitelist`, `--topic-white-list` removed. `--bootstrap-server` accepts only comma-separated values.
- `kafka-configs.sh` uses incrementalAlterConfigs only (brokers older than 2.3 unsupported).
- Consumer `poll(long)` removed. Producer `sendOffsetsToTransaction(Map, String)` removed. Admin `alterConfigs` removed.
- Streams: public APIs deprecated before 3.6 removed (except `JoinWindows.of()` and `grace()`).
- 4.1: `ConfigCommand --force` removed.

## Changed defaults

| Config | Now | Was | Since |
|---|---|---|---|
| `linger.ms` | 5 | 0 | 4.0 |
| `num.recovery.threads.per.data.dir` | 2 | 1 | 4.0 |
| `message.timestamp.after.max.ms` | 1 hour | Long.Max | 4.0 |
| `remote.log.manager.thread.pool.size` | 2 | 10 | 4.0 |
| `segment.bytes` minimum | 1 MB | smaller | 4.0 |
| Eligible Leader Replicas (KIP-966) | on for new clusters | off | 4.1 |
| `controller.quorum.auto.join.enable` | false | n/a | 4.2 |
| `group.coordinator.background.threads` | 2 | 1 | 4.3 |
| `group.consumer/share/streams.assignment.interval.ms` | 1 s | effectively 0 | 4.3 |

4.1 note: once ELR is enabled the broker-level `min.insync.replicas` is removed. Set it at cluster level if needed.

## New features worth knowing

- KIP-848 consumer rebalance protocol is GA in 4.0 and auto-enabled when the 4.0 upgrade is finalized. After consumer groups use it, downgrade is only possible to 3.4.1 or newer.
- KIP-890 transaction server-side defense enabled on finalize (4.0). Treat `TimeoutException` and `TransactionAbortableException` as reasons to abort.
- Share groups (KIP-932): preview in 4.1 (`share.version=1` via `kafka-features.sh`), production ready in 4.2. With fewer than 3 brokers set `share.coordinator.state.topic.replication.factor` and `share.coordinator.state.topic.min.isr` to 1.
- Streams Rebalance Protocol (KIP-1071): early access in 4.1, production ready for its core feature set in 4.2. Do not migrate classic groups on 4.2.0 (KAFKA-20254), use 4.2.1 or later.
- 4.3: log directory cordoning (KIP-1066), `dsl.store.format` (`DEFAULT` or `HEADERS`) for the Streams DSL.

## Migration gotchas

- Upgrade clients first and one at a time, and check none are older than 2.1.
- 4.0 metadata downgrade is not supported. 4.1 same upgrade procedure as 4.0. 4.2 has no metadata changes so metadata downgrade is supported. 4.3 includes metadata changes so it is not.
- 4.2: LIST configs stricter (no nulls, duplicates ignored with a warning). `num.replica.fetchers` minimum is 1. `cleanup.policy` may be empty (infinite retention). Custom `KafkaPrincipalBuilder` must implement `KafkaPrincipalSerde`. Many CLI options renamed (KIP-1147), old names deprecated until 5.0.
- 4.1: producer `flush` cannot be called inside a callback. `Admin.listConsumerGroups()` deprecated for `listGroups(ListGroupsOptions.forConsumerGroups())`.
- Deprecated, removal planned in 5.0: `group.coordinator.rebalance.protocols`, `kafka-streams-scala`, MX4J, `disallowed.login.modules`.

## Minor notes (patch releases worth being on)

- 4.0.1: Streams `transformValues()` to `processValues()` migration fix.
- 4.1.1: Streams memory leak (KAFKA-19748) and a potential data loss fix (KAFKA-19479). Streams users go straight to 4.1.1 or later.
- 4.1.2: rare producer bug that could send a record to the wrong topic (KAFKA-19012).
- 4.2.1: share group deadlock fix, rolling upgrade `UnsupportedVersionException` for transactional producers, classic-to-streams migration fix.
- 4.3.1: Streams native memory leak fixes, `OffsetOutOfRangeException` on restart, Admin partition-leader API hang.

## Not covered by the notes above

- Minimum Java version for 4.1 to 4.3 was not restated in those sections. Assume unchanged from 4.0, unverified.
